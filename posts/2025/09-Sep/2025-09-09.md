Last night I got a lightweight Kubernetes cluster running with k3s on a Fedora VM. Here are some quick tips for making it usable as a regular user account.

Installation is a breeze with the quick-start script from k3s. No added options required. This gets everything setup including `kubectl`, a kubeconfig, and starts the k3s systemd service.

You can verify the cluster with:
💲systemctl status k3s
💲kubectl get nodes

However, by default, `kubectl` in k3s points to the system kubeconfig at `/etc/rancher/k3s/k3s.yaml` which is owned by root, uses the localhost IP, and is not directly accessible to non-root users.

If you want to run `kubectl` as a non-root user (which you should!), this setup won't work out of the box.

To work around this:
1️⃣ You'll need to copy the kubeconfig to your user's home directory
#️⃣ mkdir -p ~/.kube
#️⃣ sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
#️⃣ sudo chown $(id -u):$(id -g) ~/.kube/config

2️⃣ Update the server IP: change the localhost IP to the VM's actual IP
#️⃣ sed -i 's/127.0.0.1/<vm_ip>/' ~/.kube/config

3️⃣ Set the KUBECONFIG environment variable so `kubectl` looks for your user config
#️⃣ export KUBECONFIG=~/.kube/config

You can make the environment variable KUBECONFIG permanent by adding it to your .bashrc file.

Now `kubectl` works under your non-root user without relying on sudo or a special root context!

👉 Why does this matter?

It keeps your workflow clean and secure, avoids running kubectl as root, and follows best practices by keeping kubeconfigs scoped to individual users.

If you are running k3s locally for testing, development, or CI/CD experimentation, then this is a simple and fast approach you can repeat.
