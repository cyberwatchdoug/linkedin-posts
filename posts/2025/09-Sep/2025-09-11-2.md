Kubernetes tip: Use deployments, not bare pods, especially when learning.

Here's why deployments are essential:

🔄 **Self-healing** - Pod crashes? Deployment recreates it automatically
📈 **Scaling** - Easy to scale up/down with one command
🔄 **Rolling updates** - Zero-downtime application updates
📋 **Declarative** - Define desired state, let K8s handle the rest

But don't take my word for it, get your hands dirty and check out each essential for yourself.

Learning deployments from day one teaches you to think in terms of desired state - the foundation of Kubernetes operations.

#Kubernetes #BestPractices #DevOps #Infrastructure

```bash
# Create a deployment
> kubectl create deployment nginx --image=nginx:alpine

# Check pods for new deployment
> kubectl get pods -o wide

# export pod name
> export POD_NAME=$(kubectl get pods -o json | jq -r '.items[0].metadata.name')

# Delete pod
> kubectl delete pod $POD_NAME

# Compare pods to POD_NAME
> kubectl get pods && echo $POD_NAME

# Scale deployment
> kubectl scale deployment nginx --replicas=3

# Watch rolling changes to pods
> kubectl get pods -w -o custom-columns="NAME:.metadata.name,IMAGE:.spec.containers[*].image"

# Update deployment image
> kubectl set image deployments nginx nginx=nginx:alpine-slim
```
