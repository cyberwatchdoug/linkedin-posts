Don't let the command line intimidate you. It's actually your best friend for building confidence and skill!

When I set up my labs repo on a new VM for homelab experiments, I left VSCode behind and went all-in on the CLI.

It feels empowering to handle SSH configs, Git settings, and remote updates without relying on any UI tools.

Here are the essentials I covered:

🗝️ Generated (or found) my SSH keys so GitHub would trust my machine
🖥️ Added my public key to GitHub
😁 Setup my commit identity so my changes are always attributed
📋 Checked and updated my remote repo config to use SSH instead of HTTPS
🗃️ Made sure my VM's SSH config was on point

Now? No more credential prompts. Just seamless git CLI work while I build, break, and rebuild.

I'm curious what others do: Do you stick to the CLI, mix in some UI, or use shortcuts I might not have tried?

For instance, don't just rely on VSCode to get your Git repositories setup. Do it yourself in the CLI!

Getting your local Git repository set up with GitHub using only the CLI is pretty straightforward.

Here’s the steps you’ll want to cover:

🗝️ Generate or locate your SSH keys
Use [ssh-keygen] if you don’t already have a key pair. Your public key is typically stored at [~/.ssh/].

🖥️ Add your SSH key to GitHub
Copy the contents of your .pub key file and add it under GitHub → Settings → SSH and GPG keys. This allows GitHub to trust your machine.

😁 Set up Git identity
Configure your global identity for commits:
[git config --global user.name "Your Name"]
[git config --global user.email "your_email@example.com"]

📋 Check your remote configuration
In your local repo, run: [git remote -v]

If the URL shows https://..., switch it to SSH:
[git remote set-url origin git@github.com:OWNER/REPOSITORY.git]

Replace OWNER with your github username, and REPOSITORY with the repository name.

🗃️ Ensure your SSH config is in place
Confirm your SSH client knows how to reach GitHub by editing your [~/.ssh/config]

```
    Host github.com
      HostName github.com
      User git
      IdentityFile ~/.ssh/<id_file>
```

Make sure the IdentityFile points to the private key (no .pub extension).

Once that’s configured, you can pull, push, and clone without needing to type your GitHub credentials every time.
